# Truck handling lab

Open **Truck handling lab** at the bottom right of the main menu, or run `res://scenes/handling_lab.tscn` with F6. From a terminal: `godot --path Food_Truck_Drive res://scenes/handling_lab.tscn`.

The flat test pad has no patrons, traffic, police or random choices. Each automated run lasts eight seconds at 60 Hz physics: one second to settle, three seconds of acceleration, then a normal turn or brake-and-steer power slide with countersteering, followed by braking. The donut sequence stays stationary for four seconds before applying throttle, brake and steering together. It resets the truck between runs. **Repeat all three** cycles through the maneuvers. The actual truck controller, suspension and collisions compute the resulting motion; the lab does not move it along a prerecorded pose path. Inputs are reproducible, while handling edits deliberately change the resulting path.

The overlay shows speed, rotation rate, slip angle, slide blend and a ground trail. Sliders apply immediately. **Pause**, **Restart**, and **Manual drive** let you compare or drive yourself with the usual controls. Restart after a change to compare from the same initial state. Original reproduces the existing handling. Gentler slide lowers turning force from 4.5 to 2.2, lowers slide steering, increases slide grip and accelerates grip recovery. It is an optional starting preset; game defaults stay unchanged until you choose a profile.

**Record tuning** starts a fresh run and records inputs and motion every physics tick, property/profile changes at their exact tick, and each run's starting values. **Stop + save recording** writes JSON to `user://handling/captures/`. Captures finish automatically after ten minutes to bound memory. Closing the window or returning to the menu also saves an active capture. Pause produces no motion samples. The capture contains versioned input definitions and settings, position, speed, heading, turning rate, slip and slide blend. This is handling telemetry, independent of debug replay recording. It never enables replay capture or changes the editor's frame cap.

**Save profile** stores a named profile in `user://handling/profiles.json`. **Use as default** also associates it with the Truck ID field (`food_truck` for the current truck); subsequent single-player trucks with that ID load it automatically. Local defaults are not applied in multiplayer, where peers must share the same authored handling. Unknown properties, nonnumeric values and out-of-range values are rejected or clamped when loading. **Open saves** opens `%APPDATA%/Godot/app_userdata/OnTheFly/handling/` on Windows.

For future truck types, give each scene a different `handling_id`. **Export .tres** writes a portable `TruckHandlingProfile` resource to `user://handling/exports/`. Copy the resource into the project's assets and assign it to the truck's **Handling Profile** inspector field to ship that truck's default with every client. Profiles contain only handling properties; they do not store damage, upgrades or gameplay state. A matching local default overrides the authored profile in single player; turn off `use_saved_handling_default` on a truck to use its authored settings exclusively. Trucks without a profile retain their scene values.

Validation: `tools/handling_lab_test.gd` exercises matching repeated physics traces, all three input sequences, live changes, capture events, profile persistence and authored resources. Run it graphically with `--fixed-fps 60 --script res://tools/handling_lab_test.gd`; that option applies only to the separate validation process.
